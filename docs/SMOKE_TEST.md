# v0.1 desktop smoke test

Run on a physical macOS and Windows computer after following [SETUP.md](SETUP.md). Allow about **10 minutes after installation/build**; a large initial scan may take longer. This is a manual acceptance checklist, not a statement that either platform has already passed. Record the tag/commit and OS for each run.

Prepare a disposable folder with 200–500 images, including a Chinese filename, two visibly different images for replacement, and an SD WebUI/ComfyUI PNG if available. Once the fixture script is present, `node scripts/generate-fixtures.mjs <absolute-new-folder> 300` produces suitable PNGs without overwriting existing files. Use a separate small file for the upload step.

No asset file contents are included.                                                                             |

Also check the platform-specific case applicable to the machine:

- **macOS:** A protected folder denied access should name Full Disk Access for the terminal/Node. Grant it and retry. Include a Chinese filename; where possible test files created with different Unicode normalization spellings.
- **Windows:** Try a long nested path (over 260 characters) and an unreadable/locked file. A failed operation must show a recoverable error without losing saved catalog state. PowerShell `.cmd` commands should avoid execution-policy issues.

Canvas/slot/matrix boards and brand/whole-library exports are **not v0.1 checks**. Add their drag/replace/export checks when v0.2 is available; their absence is not a successful canvas/export test. The v0.1 export exercised here is diagnostics, plus individual version download if needed.

## Report a result

Record pass/fail and the first failing step, exact tag/commit, OS version and architecture, Node/pnpm versions, terminal output, and expected versus actual behavior. Attach the exported diagnostic ZIP and a screenshot if useful. If startup fails, attach the terminal error and relevant log lines from the paths in SETUP.md. Inspect logs for private filenames or metadata before sharing; do not include credentials.

The coordinator records actual desktop results and limitations in the milestone report. Linux headless Chromium, simulated Windows paths, and unit-tested permission messages do not substitute for this checklist.
