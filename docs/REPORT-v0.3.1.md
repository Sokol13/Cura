## Final runtime and PSD evidence

The final Node 24 clone passes all 596 local unit/tool cases and all 33 browser scenarios. Independent fresh installs take 2.0 s on Node 22 and 1.908 s on Node 24 with a warm download store; no native compilation or dependency changes are required. Normal starts take 21.6 s and 20.3 s respectively, including building the application. Both automatically opened browser sessions preserve Chinese library identity after reload and in the closed database. Linux XDG/headless-browser evidence does not establish physical desktop shell behavior.

Final complete-server PSD fixtures retain original/snapshot hashes and meet the unchanged strict <10 s / <500 MB bounds on both runtimes. Node 22: 225/426/634 ms and 220/220/230 MB absolute peak RSS. Node 24: 220/381/550 ms and 376/388/372 MB. [Node 22 benchmark](evidence/v0.3.1/final-node22-psd.json), [Node 24 benchmark](evidence/v0.3.1/final-node24-psd.json). These are generated files spanning the two reported endpoint sizes and an 8192×8192 proxy; the actual user PSDs remain untested.

## Upgrade preservation and remaining experience work

The exact released v0.3.0 → version-bumped v0.3.1 upgrade passed [13 checks](evidence/v0.3.1/upgrade.json), preserving every original row/column/ID/timestamp in 48 legacy tables and all seven retained-version hashes. Both source trees were freshly built before execution. The additive scan-summary table persists correctly; two reopens retain an identical logical digest and clean integrity/foreign-key checks.

The ordered v0.4.0 follow-up remains: folder-first onboarding, dated Inbox folders and migration, canvas-to-slot dragging, side-by-side slot history, exact export dependency counts, and investigation of the reported Windows canvas/CDP freeze. These are not claimed complete in v0.3.1.
