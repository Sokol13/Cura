**Status: locally verified release candidate; not tagged.** All three P2 capability groups and inherited local acceptance passed. Candidate main CI, including mandatory genuine cloud acceptance, and final publication remain pending. This report does not authorize release yet.

The published predecessor is [v0.2.0](https://github.com/Sokol13/Cura/releases/tag/v0.2.0). Foundation main commit `e0efb4b` passed [CI 37207974648](https://github.com/Sokol13/Cura/actions/runs/37207974648). Final commit, CI and release links will be recorded after verification.

## Delivered implementation

- Reviewable tag/name proposals with explicit offline metadata rules and a real configured vision adapter. Exact-version/field guards, selective apply/undo, bounded worker/network processing, cancellation, persisted history and honest model/derivation provenance.
- Portable readable names, archive/restore controls and saved non-final archive rules. Source files and historical names remain unchanged. Historical final owners are protected, newly assigned finals restore visibility, and bounded archive batches keep local requests responsive.
- Retained UTF-8 text/Markdown/Fountain scripts with editable character/prop/scene lists, checked exact line excerpts and optional text-provider extraction. Editable setting documents copy exact-version metadata/provenance and export Markdown/JSON.
- Optional server-owned Supabase authentication, verified incremental immutable files and metadata, durable operations/cursors, local-wins conflict snapshots, complete P0/P1 and completed automation graph transfer, and owner/editor/viewer shared libraries. Missing configuration remains explicit local mode.
- FCPXML 1.7 timelines with ordered historical pins, inspected video timing, exact rational frame arithmetic, board import, retained-media ZIP/XML and standalone hash-checking relinking.
- Neutral export includes display/archive metadata, completed automation/scripts/documents, sync conflict snapshots and completed FCPXML requests with dependency closure. Device-specific registrations, credentials, active jobs and generated download caches remain private/local.

No P2 capability group is omitted. External model/project configuration is optional for those providers; it is not needed to use local library features, metadata rules, structured scripts, setting documents or FCPXML.

## Limits and user action

- Physical macOS/Windows, protected folders/long paths, desktop browser/video behavior, session-file ACLs and Final Cut Pro import remain [manual smoke checks](SMOKE_TEST.md). Linux, real local Supabase and DTD checks do not establish those outcomes.
- A hosted Supabase project requires applying the supplied migration/policies and configuring Auth/public keys. Hosted quotas, organization policies and deployment configuration are unverified. Cura never uses a service-role key in application/browser configuration; the disposable test seeder uses one privately only to create test accounts.
- The small verified visual model can hallucinate details and did not reliably emit structured JSON. Caption-derived fields remain labelled, reviewable suggestions. No claim of general recognition accuracy, Chinese-language quality or arbitrary-prose extraction is made.
- Structured offline script extraction recognizes documented cues. Deterministic setting documents label absent metadata rather than inventing it. Provider-based extraction requires explicit server configuration and source review.
- FCPXML supports the documented serial-spine subset, PNG/JPEG stills and bounded constant-frame-rate supported MP4/MOV headers. Header validation is not video decoding. Generated packages are local operational artifacts; transfer their ZIP and relink on the editing machine. Cloud does not restore unavailable ready-download paths.
- Existing preview and classic ZIP limits from v0.2 remain. Model tooling, Docker/Supabase CLI, Python/lxml and Apple's downloaded DTD are development/provider prerequisites, not Cura runtime dependencies.

Run the smoke checklist on Mac and Windows and report the first failure with tag/OS and sanitized diagnostics. Incoming desktop bugs take priority. No credentials are required for local use.
