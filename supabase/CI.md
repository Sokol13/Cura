# Required cloud acceptance

`.github/workflows/cloud-check.yml` is called by both CI and Release. Release publication depends on its successful result as well as the normal validation job. It requires no repository or hosted Supabase secrets.

CI and Release each call this workflow with a required `node-version` input for both Node 22 and Node 24. Every matrix cell runs the entire sequence below in its own Ubuntu runner, using the current patch of that major, pnpm 10 from `packageManager`, Supabase CLI 2.119.0 and the checked-in `config.toml`. A manual workflow dispatch selects one major for a focused rerun; it does not replace the two mandatory matrix cells. The disposable project is `cura-ci`; only PostgreSQL, Auth, PostgREST, Storage and the gateway run. The Data API exposes `public`, with automatic grants disabled. Email confirmation is disabled only for this local fixture.

Checks run in this order:

1. SQL/RLS/CAS, concurrent commits, membership revocation and immutable Storage. This suite resets only Cura's protocol schema and policies in the disposable runner database.
2. Real sign-in, refresh, private session persistence and verified file transfer.
3. Two-device graph replay, automation history, conflicts, uncertain/local edits, offline transport recovery and corrupt peer rejection. JSON reports explicitly reject skipped or missing required tests.
4. Security advisors, failing at warning level.
5. Four generated Auth accounts and the configured two-server browser workflow, using actual owner/editor/viewer permissions.

The status file, generated browser passwords, JSON reports and all cloud-test stdout/stderr are restricted to the runner's private temporary directory. They are never artifacts or stdout. Vitest and Playwright use JSON-only reporters; a tested helper prints only fixed phase labels and bounded numeric counts, never assertion values, test titles, errors or captured output. Missing/invalid reports, nonzero process exits, skipped tests and flaky browser results fail the job. Startup failures print a generic phase failure and only the disposable Docker container names/status; raw startup logs remain private. The configured browser harness disables traces, videos and automatic screenshots; its intentional screenshot masks account details. An `always()` cleanup stops only `cura-ci`, discards its disposable volumes and deletes private files.

The normal offline unit suite may skip the three cloud-only test files when `CURA_SYNC_TEST_STATUS` is absent. The required cloud job sets and validates that private status file, then fails if any of those tests are skipped. Its browser fixture is generated by `seed-browser-fixture.mjs`; see [the protocol and fixture guide](README.md) for the separate local command.

No local stack is required to lint or inspect the workflow. A full local replay of this CI job requires Docker and unused ports 54320–54322; use a separate disposable environment from an active development stack.
